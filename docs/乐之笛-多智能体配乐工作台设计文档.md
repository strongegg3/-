# 乐之笛 · 多智能体配乐工作台 设计文档

> 给剪辑师用的多智能体配乐工作台——你说清楚要什么，一群智能体帮你从各个渠道挖合适的歌。

## 一、产品定位与核心价值

### 目标用户
做Vlog/短视频/纪录片的剪辑师，经常为找配乐发愁，对音乐质感有要求，不满足于热歌榜。

### 核心差异化
和普通搜歌工具的区别：
- **理解剪辑需求**：不是"输入关键词→给你热门歌"，而是"理解你的剪辑需求→按用途场景（开场/转场/BGM等）从多个渠道找质感好、适合当配乐的歌"
- **多渠道覆盖**：歌单/个人收藏/影视原声等多渠道并行，不会漏掉那些小众但好用的曲子
- **透明的推荐依据**：告诉你"这首歌为什么适合"，而不是丢一首莫名其妙的歌
- **反馈式迭代**：能根据你的反馈不断调整，越用越懂你

## 二、多智能体架构与协作流程

### 核心Agent角色

#### 1. 规划Agent（Planner）— 需求挖掘者
- 通过对话澄清用户需求：视频内容、目标情绪、画面场景、节奏需求、用途（开场/转场/高潮/BGM/结尾）
- 输出结构化的需求摘要，明确"要找什么样的歌，用来干嘛"

#### 2. 专用寻找Agent（Specialized Finders）— 按用途分工的挖歌人
按剪辑用途细分，每个Agent有自己的搜歌逻辑和偏好：
- **开场Agent**：找适合做开头的曲子（intro感、环境音、缓慢进入、有氛围感）
- **BGM Agent**：找背景音（轻人声/纯音乐、不抢旁白、持续氛围感）
- **转场Agent**：找适合转场的曲子（间奏、build-up、纯音乐段落、有节奏感）
- **高潮Agent**：找适合高潮的曲子（副歌、能量强、有记忆点、情绪饱满）
- *（结尾Agent第二阶段再加）*

#### 3. 分析Agent（Analyst）— 质检员
- 给每首歌打标签（情绪/场景/BPM/能量/人声类型）
- 标注适用段落（开场感/BGM感/转场感/高潮感，轻量标注）
- 写推荐理由，筛掉不合适的，选出Top N

#### 4. 反馈Agent（Feedback）— 调参师
- 把用户的自然语言反馈（"太吵了""更悲伤一点"）翻译成需求调整
- 和规划Agent协作，生成新的需求，重新走流程

### 协作流程

```
用户输入需求
    ↓
规划Agent → 澄清追问 → 生成需求摘要（含用途：开场/转场/BGM...）
    ↓
根据用途，派给对应的专用寻找Agent
    ↓
专用寻找Agent并行工作，从多个渠道挖歌
    ↓
分析Agent统一打分、打标签、筛选、排序
    ↓
结果按渠道分Tab展示给用户
    ↓
用户反馈 → 反馈Agent + 规划Agent → 新需求 → 重新来一遍
```

**协作模式**：按需分配，不是所有Agent都干活。规划Agent根据需求派活给对应的专用Agent，效率更高。

## 三、专用寻找Agent的搜歌逻辑

每个专用Agent都有自己的"搜歌经验"，知道什么特征的歌适合自己的用途。它们从相同的渠道里挖歌，但筛选标准和关键词不一样。

### 开场Agent
- **搜什么**：intro、环境音、氛围感、缓慢进入、纯音乐开头
- **关键词策略**：intro、开场、环境音、氛围、ambient、intro版、纯音乐开头
- **偏好特征**：开头音量低、逐渐进入、有环境感、人声出现晚、BPM偏低
- **特别技巧**：优先看专辑intro曲、歌单里标"开场""前奏""氛围"的

### BGM Agent
- **搜什么**：不抢人声、持续氛围感、轻人声或纯音乐、节奏平稳
- **关键词策略**：BGM、背景音乐、纯音乐、轻音乐、instrumental、lofi、chill
- **偏好特征**：人声少或轻、节奏变化小、能量中等偏低、持续时间长
- **特别技巧**：优先从"BGM""轻音乐""工作学习"类歌单里挖

### 转场Agent
- **搜什么**：有节奏感、间奏、build-up、能卡点、纯音乐段落
- **关键词策略**：间奏、纯音乐、节奏、beat、instrumental、remix版
- **偏好特征**：有清晰鼓点、BPM适中、有渐进感、适合卡点剪辑
- **特别技巧**：找副歌前的build-up段落、有明显节奏变化的

### 高潮Agent
- **搜什么**：副歌、能量强、有记忆点、情绪饱满
- **关键词策略**：副歌、高潮、燃、高能、史诗、epic、高潮版
- **偏好特征**：副歌好听、能量高、有记忆点旋律、情绪张力强
- **特别技巧**：优先看播放量高的热门曲（高潮部分大众认可度高）

### 渠道策略（按重要性排序）

**第一阶段**：
1. **歌单挖掘**：网易云精品歌单 + 达人歌单（按分类搜，再按用途筛选）
2. **个人收藏**：接入用户网易云的喜欢/自建歌单（从用户私藏里挖）

**第二阶段以后**：
3. **UP主推荐**：人工维护的优质UP主歌单池
4. **影视原声**：电影/动漫/游戏OST的情绪段落

## 四、展示与交互设计

### 整体布局
保持现有三栏结构，右侧推荐区做渠道Tab切换：

```
┌──────────┬──────────────────┬─────────────────────┐
│ 历史任务  │   对话 + 需求摘要  │   推荐结果          │
│          │                  │  [渠道Tab切换]       │
│          │  规划AI对话区     │  精选歌单 | 我的收藏  │
│          │                  │                     │
│ 模型配置  │  需求摘要编辑器   │  歌曲卡片列表        │
│          │                  │  · 推荐依据          │
│          │  [确认生成歌单]   │  · 标签/适用段落     │
│          │                  │  · 平台跳转          │
└──────────┴──────────────────┴─────────────────────┘
```

### 推荐结果区

**顶部Tab（按渠道分）**：
- 🎵 **精选歌单** — 从网易云歌单里挖到的
- 💾 **我的收藏** — 从用户网易云个人歌单里挖的（需登录）
- 🎬 **影视原声** — 第二阶段做
- 📺 **UP主推荐** — 第二阶段做

**歌曲卡片内容**：
- 歌名 + 艺术家
- 推荐依据（为什么适合当前需求）
- 标签：情绪/场景/BPM/能量
- 轻量段落标注（如"🎬 开场感""🎵 副歌感""🔇 纯音乐"）
- 平台来源 + 跳转链接

### 反馈区
预设标签 + 自定义输入，反馈后重新走完整流程（规划Agent微调需求 → 专用Agent重新搜 → 分析Agent重排）。

## 五、第一阶段实施范围

先做核心闭环，把架构跑通。

### 必做（核心）
1. **规划Agent升级**：追问时要问清楚"用途"（开场/BGM/转场/高潮），需求摘要里包含用途字段
2. **4个专用寻找Agent**：开场Agent、BGM Agent、转场Agent、高潮Agent
3. **2个渠道接入**：歌单挖掘（已有基础，改造为各Agent可调用）、个人网易云歌单
4. **分析Agent增强**：给每首歌打适用段落标签（开场感/BGM感/转场感/高潮感）
5. **结果展示**：按渠道分Tab展示（精选歌单 / 我的收藏），卡片显示推荐依据和适用段落标签
6. **反馈迭代**：每次反馈重新走"规划微调→专用Agent重搜→分析重排"完整流程

### 第二阶段以后
- 结尾Agent
- 影视原声渠道
- UP主推荐渠道（人工维护）
- 更精细的段落标注
- 收藏/歌单管理

## 六、技术架构（基于现有代码）

### 后端（Node.js + Express）
- `services/ncm.js` — 网易云单曲搜索
- `services/ncm-playlist.js` — 网易云歌单搜索（已有，需改造支持多用途筛选）
- `services/ncm-user.js` — 新增：用户歌单/收藏获取（需登录）
- `routes/search.js` — 搜索路由（需扩展，支持用途参数）

### 前端（原生JS，现有架构）
- `js/planner.js` — 规划Agent（升级：加用途追问）
- `js/finder.js` — 寻找Agent（升级：拆分为4个专用Agent + 渠道层）
- `js/analyst.js` — 分析Agent（升级：加适用段落标签）
- `js/feedback.js` — 反馈Agent（升级：和规划Agent协作）
- `js/render.js` — 渲染（升级：渠道Tab + 段落标签展示）
- `js/state.js` — 状态管理（升级：用途字段 + 登录态）

### 数据流向
```
前端触发搜索
  → 传用途 + profile（场景/情绪/BPM/能量/人声偏好）
  → 后端根据用途调用对应的寻找逻辑
  → 每个寻找逻辑从不同渠道（歌单/个人收藏）挖歌
  → 统一归一化格式返回
  → 前端分析Agent打分、打标签、排序
  → 按渠道分Tab展示
```
